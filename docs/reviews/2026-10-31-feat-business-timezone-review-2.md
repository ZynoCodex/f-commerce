## Minor

### 🟡 Test fixtures still feed `logoUrl: ''` although the API and the entity can no longer produce it — `frontend/src/app/onboarding/page.test.tsx:32`, `backend/src/presentation/controllers/business.controller.route.test.ts:272`

**Problem**: `incompleteBusiness` in the onboarding page tests mocks `GET /api/business/me` and `GET /api/business/onboarding` with a top-level `logoUrl: ''`. After this fix the real endpoints answer `null` for a logo-less business — the response contract now rejects `''` by a test added in the same slice — so the fixture pins a shape that cannot occur. The backend route test at line 272 goes further: it mocks a `Business` domain entity carrying `logoUrl: ''`, which the entity's new doc comment (`business.entity.ts:17-21`) explicitly declares impossible. The assertions in the route test happen to only cover the 403 gate, so nothing breaks today; the drift is inert but real.

**Why it matters**: The whole point of the fix is that the empty string never crosses the API boundary or the entity. Unit fixtures that still use `''` quietly teach the next reader the old shape, and the onboarding suite never proves the no-logo path against the `null` the API now actually sends. The first consumer that validates a response with `BusinessResponseSchema` — or the first person who trusts the fixtures as API documentation — is misled.

**Suggested fix**: Change the top-level `incompleteBusiness.logoUrl` (and any other business-level, non-draft fixture) to `null`, keeping `''` inside `onboardingDraft` fixtures only, where the draft schema legitimately allows it. Update the route test's mock entity to `logoUrl: undefined` like the neighboring no-logo test at line 240 already does. No product code changes.

**Resolved 2026-10-31**: `incompleteBusiness` now carries `logoUrl: null`, so the onboarding suite exercises the shape the API sends. The route test's mock entity now carries `logoUrl: undefined`, matching the neighboring no-logo test. Every remaining `logoUrl: ''` in tests is deliberate: nine onboarding draft fixtures and ten cases prove the draft schema still accepts it, the response schema rejects it, the repository normalizes it on write, and a row already stored that way reads as no logo. Frontend 301, backend route tests 54, lint, typecheck and format clean.
